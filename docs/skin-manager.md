# 皮肤管理器（本皮肤的前置条件）

本文按管理器 **0.1.6** 编写（2026-10-29 本机实测）。

`dsh-skin-hdd-fairy` 不是一个"自己挂上去"的插件：它是一张**被管理的皮肤**。负责发现、切换和渲染它设置的，
是另一位作者（[@smalltailqwq](https://github.com/Small-tailqwq/dsh-deep-whale)）写的通用模块：

```
@smalltailqwq/dsh-client-ui-skin-deep-whale-manager     （MIT）
```

**不装它，DSH 里根本不会出现「设置 → 皮肤管理」这个页面，皮肤装了也不可见。**

## 它到底替皮肤做了什么

| 职责 | 说明 |
|---|---|
| **发现** | 扫当前 profile 的依赖，找出所有带有效 `skin.json` 的包 |
| **互斥切换** | 在「官方默认」与任意一张皮肤之间二选一；同一时刻只有一张皮肤生效 |
| **渲染设置项** | 把皮肤通过版本化协议声明的开关 / 下拉 / 滑杆画成控件（本皮肤的 7 项就在这里） |
| **持久化** | 按 `skinId` 存进浏览器 `localStorage`；皮肤自己不写存储 |
| **启动兜底** | 每次启动检查启停状态；发现两套及以上皮肤同时启用时，**原子回退到官方默认** |
| **兼容性放行** | DSH 升级后，对 `dshCompatibility` 不匹配的皮肤自动停用并标注，确认后可手动放行 |

它只处理"声明、持久化、时间规则"，不碰皮肤的 DOM / CSS —— 所以皮肤出问题时，管理器不该背锅；反过来，
管理器缺失时皮肤的一切都不会发生。

## 安装：三步

```powershell
# 0) 先完全退出 DSH 桌面版

# 1) 装管理器（只需一次；之后装任何皮肤都不用再装）
dsh plugin --profile desktop add '@smalltailqwq/dsh-client-ui-skin-deep-whale-manager'

# 2) 装皮肤
dsh plugin --profile desktop add dsh-skin-hdd-fairy
```

```powershell
# 3) 启动 DSH → 设置 → 皮肤管理 → 切到「HDD Fairy」
```

也可以在 DSH 里用 **插件 → 添加插件** 粘贴上面两个包名，效果一样。

### 两个容易装废的地方

1. **`--profile` 的名字**：本机是 `desktop`，管理器官方 README 的示例写的是 `web`。
   装到另一个 profile 里，当前界面就是看不到 —— 不是包坏了。
   不确定就先看一眼 `%USERPROFILE%\.dsh\profiles\` 下有哪些目录，或者直接用界面里的「添加插件」。
2. **首次装完要重启一次 DSH**。管理器在**启动时**做兜底检测和皮肤发现，不重启它还没来得及接手。

### 版本要求

| 组件 | 要求 | 来源 |
|---|---|---|
| DSH 桌面版 | ≥ `0.1.7-rc.1` | 管理器的 `peerDependencies` |
| 本皮肤 | `0.2.1-rc.3` | `skin.json#dshCompatibility`（写成 `0.2.1rc3`） |

## 别同时启用两套皮肤

管理器启动时如果发现 **≥ 2 套皮肤同时启用**，会把启停状态**原子回退到官方默认** ——
表现就是"什么都没启用、界面变回原样"，而不是报错。

所以 `packages/dsh-hdd-visual`（早期独立版）**不要和本皮肤一起开**：两者功能重叠，且会触发上面的回退。
同一时刻只留一张皮肤，是这套机制的硬规则。

## 「设置 → 皮肤管理」里，真正值得动手的东西

页面分成两块：上面是**皮肤列表**（切换用），下面是**当前皮肤自己的设置**（本皮肤有 7 项）。
第一次装建议**全部保持默认**，先确认徽记、配色、品牌位确实出现了，再去动开屏。

### 第一步不是设置，是切换

列表里选中「HDD Fairy」＝启用它。这一步同时做了三件事：停用其他皮肤、把本皮肤的一切挂上去、
把 `dsh.profile.bundles` 的 `dsh-skin managed` 区段改写成当前状态。

> 那个区段**归管理器所有**，手写或删改会被下次切换覆盖。区段外的用户 YAML 不会被碰。

### 7 个设置项（按重要性排序）

| 设置项 | 键 | 默认 | 建议 | 生效 |
|---|---|---|---|---|
| **开屏内容** | `splashSource` | `none` | 想开机动画就放素材后改成 `auto`；不想每次等就留着 `none` | 下次启动 |
| **开机动画** | `splash` | 开 | 留开 | 下次启动 |
| 动画结束点 | `animEndS` | `0`（播完整段） | 自己的片子片尾冗长时设 5–8 秒 | 下次启动 |
| 回合提示音 | `cues` | 开 | 留开；嫌吵就关 | **立即** |
| 问候语音 | `voice` | 开 | 有素材才有声音；没有素材时开与关没有区别 | **立即** |
| 徽记尺寸 | `markSize` | 60 | 40–80 之间调；收起 sidebar 时固定 30 | **立即** |
| 徽记光晕 | `markGlow` | 开 | 光晕 / 涟漪 / 周期性撕裂的总开关 | **立即** |

**"新装了却没有开机动画"的第一嫌疑永远是 `开屏内容 = none`** —— 发布包不带任何素材，
默认直接进界面是有意为之，不是坏了。

**"下次启动"和"立即"的区别**：开屏在文档加载时只挂载一次，所以前三项只影响下一次启动；
后四项走 `<body>` 上的 CSS 变量与属性，改完立刻变。

### 两张推荐配置

```
只想换个界面外观（推荐第一次用）
  splashSource = none, splash = 开, cues = 开, markSize = 60, markGlow = 开

想要 HDD 开机那一下
  1. 设置 → HDD Fairy 素材 → 导入 boot.mp4（或手放进 assets/）
  2. splashSource = auto，animEndS = 6（截掉片尾）
  3. 重启 DSH
```

## 管理器里有、但本皮肤用不到的两项

| 管理器功能 | 为什么本皮肤用不到 |
|---|---|
| **桌面图标跟随皮肤**（Windows，默认关闭） | 需要皮肤在 `skin.json` 里声明 `desktopIcon`（包内 `.ico` 相对路径）。本包**没有声明**，所以开关对本皮肤无效 —— 打开也会还原成官方图标 |
| **不那么二次元模式**（按本机时间设置显示/隐藏时段） | 由皮肤声明 `visibility-schedule` 类型的设置项才会渲染。本包**没有声明**，所以页面里看不到这一项 |

这两项都是"皮肤支持才有"的通用能力，不是管理器少了什么。以后想加，改皮肤就行。

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 设置里找不到「皮肤管理」 | 管理器没装 / 装完没重启 / 装进了另一个 profile |
| 列表里没有「HDD Fairy」 | 皮肤没装进**同一个** profile；或 `skin.json` 不可 `require.resolve`（检查 `package.json#exports` 有 `./skin.json`） |
| 切换了，界面没变 | 只改了"下次启动"类的项；或当前皮肤其实没切过去（看列表里的选中态） |
| 两张皮肤都在列表里却都没生效 | 触发了"≥2 套同时启用 → 回退官方默认"，重新切换一次即可 |
| DSH 升级后皮肤变灰 / 自动停用 | `dshCompatibility` 与新版本不匹配。管理器会标出这类皮肤，点「切换」并确认后，只会放行「这个皮肤版本 + 这个 DSH 版本」 |
| 设置突然全丢 | 值存在浏览器 `localStorage`（按 `skinId`）。清缓存、换机器、换 profile 都会丢，皮肤包本身不保存 |
| 窄窗口（< 1024px）点「插件」回不到对话 | 再点一次已打开的那个入口即可 —— 与 DSH 侧栏折叠是同一个断点 |
| 已经装了 `@linxin666/dsh-web-all` | **不要**再装本管理器，也不要装本皮肤：dsh-web 自带皮肤中心，两种发行方式不能在同一 profile 叠装 |

卸载与回滚见根 README 的同名小节；素材位置见 [`asset-convention.md`](asset-convention.md)。
