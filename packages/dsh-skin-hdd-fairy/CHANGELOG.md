# 变更记录

本文件记录 `dsh-skin-hdd-fairy` 的对外变更。格式参考 Keep a Changelog，版本语义参考 semver。

## 未发布

### 新增

- **左下角状态文字**：徽记右边显示一个短词，与提示音共用同一条运行状态流——
  `已就位`（打开软件）、`思考中`（运行开始，圆点呼吸）、`已完成` / `出错了`（运行结束）、
  `空闲中`（结束后 8 秒）。文字**渐显入场**：初始即渲染为透明（`opacity: 0`），待
  「壳子已挂载且开屏标记已撤」后再翻转 `data-shown` 触发过渡（默认 1200ms、3px 上移，
  可用 `--hdd-status-in-ms` 调整）——用过渡而不是关键帧动画，是因为 `animation` 会先在
  自然不透明度上绘制一帧，看起来像"先弹出再渐变"；且起算点若放在挂载瞬间，渐变会在界面
  出现之前就播完，观感同样是"突然出现"。状态切换只换色、不重播动画；
  关掉「回合提示音」时文字照常显示（只有声音被开关管住）；
  收起成 56px rail 时文字隐藏；`prefers-reduced-motion` 下不渐显、不呼吸、不变色。
- `/hdd/cue` 响应新增 `running` 与 `last`（最后一条 cue）：客户端**每次轮询都拿 `running` 校正标签**——
  cue 事件是尽力而为的（重载、隐藏标签页、宿主重启都可能丢一条），丢了 `done` 就会一直停在
  「思考中」；以 `running` 为准，这类情况会在一个轮询周期内自愈，`last` 只用来区分失败还是完成。

### 修复

- **诊断日志一直静默失败**：`lib/index.js` 里 `MAX_LOG_BYTES` 被引用却从未声明，`/hdd/report` 的每次写入
  都在那一行抛 `ReferenceError` 并被路由自身的 `catch` 吞掉——**返回 204，日志里却什么都没有**。
  客户端上报（`apply`、`assets`、`splash-*`、`cue-play`）因此全部丢失，排查一直在"看不见客户端"的状态下进行。
  现已补上常量（2 MB），并让 `GET /hdd/report?event=…&detail=…` 也能写入（GET 通道实测最稳）。
  完整记录见 `docs/findings-2026-11-06-dsh-022-media-channels.md`。
- **提示音开头被吞掉**：提示音原先用 `<audio>` 元素播放，浏览器决定"够不够数据"才开始，
  开头几十毫秒经常被丢掉，听感就是每个提示音都从字中间起。改为**取字节 → `decodeAudioData` →
  在 AudioContext 上按采样零排期**（`playCueAudio`，带缓冲缓存与单播守卫）；
  元素播放只在该平台没有 AudioContext 或解码失败时兜底。
- **"静音一段时间后的第一声"仍会缺开头**（间歇性）：即使解码播放，音频端点闲置后（Windows 电源管理、
  蓝牙耳机）需要时间唤醒，而提前 30ms 排期的音源已经在"播放"，设备还没出声。两条对策：
  ①`ensureRunning` 成功后挂一个 **-80 dB（0.0001 增益）静音振荡器**保持流不中断（`startKeepAlive`）——
  用 0 增益有些混音器会判定为空闲，故留极小信号；
  ②所有播放的**排期提前量统一为 `PLAY_LEAD_S = 0.6s`**（原 0.02–0.05s），实测足以覆盖设备唤醒。
  每次播放另记一行 `cue-play`（`via/ctx/lead/dur/setupMs/keep`），"又吞音了"可以凭日志定位。
  素材侧已排除：`cue/*.m4a` 都是零前导静音起音，因此任何起播延迟都会被立刻听成缺字。
- **`AudioContext` 跨热重载复用**（`window.__hddAudioContext`）：热重载会让模块重新求值，
  旧上下文残留会占用 Chrome 对同页活动上下文的配额，新建的那个可能一直 `suspended`，
  于是提示音退回元素播放、开头又被吞。现在同一文档只保留一个上下文。
- **问候语音开头被吞掉**：`AudioContext` 在未经用户手势时是 `suspended`，此时
  `start(currentTime + 0.02)` 不会等待——等 `resume()` 生效时音源已经"无声播放"了几百毫秒，
  于是每次开口都从中间开始。改为**先 `resume()` 并等待其完成，再读取 `currentTime` 排期**
  （`ensureRunning`），无开屏直进的独立问候同样走这条路径，且先恢复音频上下文再预载、再播放。

- `README` 里「没有子进程」的说法不实：`/hdd/reveal` 会拉起 `explorer.exe` / `open` / `xdg-open`，
  已改为如实描述；播放路径仍然不依赖任何外部运行时。

### 说明

- **本版没有任何代码改动**，运行时行为与 0.2.0 完全一致，只有文档与声明修正。
  升级与否对功能没有影响；升级的意义在于拿到正确的归属声明。

## 0.2.0 — 2026-10-28

### 新增

- **自包含媒体层**：`/hdd/{info,asset,greeting,cue}` 四个路由并入本包（原本在 `dsh-hdd-voice`），
  皮肤不再需要第二个包；`asset-store.js` 随包分发。
- **素材页**（设置 → HDD Fairy 素材）：原生文件夹选择、目录内文件列表、导入、打开文件夹、重新扫描。
- **问候语音按文件夹分档**：`greeting/<档位>/*`，文件名随意；同时兼容旧的前缀命名（`morning-1.m4a`）。
- **品牌位**：左上角矢量图 + `Fairy` / `Ⅲ型总序式集成泛用人工智能` 两行；新会话页品牌 mark。
- **启用时把「外观」设为深色**：一次生效、可逆（停用时仅当仍是本皮肤设的值才还原）。
- **无开屏时单独播放问候语音**：直接进界面约 0.9 秒后播一次。
- 设置项：`markSize`、`markGlow`、`animEndS`（0–40 秒，步长 0.1）、`splashSource`。
- `LICENSE`（Apache-2.0）与 `NOTICE`（Fairy-DSH 徽记几何署名）。

### 变更

- **提示音改按「一次运行」触发**：一次用户消息包含多个 turn，按回合触发会连环响；
  同时监听 `agent/status` 与 `api-session/status`，进同一个幂等状态机。
- `splashSource` 取值改为 `auto` / `novideo` / `none`，**默认 `none`（直接进界面）**；旧值 `mark` 自动折成 `novideo`。
- 导入问候语音时**保留原文件名**，落进对应档位文件夹。
- 开屏在无素材时不再显示"文件缺失"提示（改为日志 + 素材页）。

### 修复

- `inventory === null` 时读取 `.field` 抛异常，导致开屏只显示提示、徽记不出现、并卡到 15 秒兜底才收场。
- 一个文档内存在多个轮询器时提示音重复播放：改为单轮询器接管 + 按 `seq` 跨实例去重 + 纪元重置。
- 文档级滚动条未被皮肤覆盖（右侧 16px 浅色竖条）。
- 停用皮肤时品牌位、CSS、定时器未完全释放。
- 素材缺失分支下的 null 解引用（同上第一条，单列以免再次引入）。

### 移除

- 对 `dsh-hdd-voice` 的隐式依赖；该包退役（见其 `DEPRECATED.md`）。
- `splashSource` 的 `backdrop` 选项——背景图的职责是给高光板当画布，不该是一个独立形态。
